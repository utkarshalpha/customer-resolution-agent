§3Service rules

  • Cancellation Rebooking Rule: if a flight is cancelled by the airline, the customer is entitled to a free rebooking on the next available flight within 24 hours, or a full refund — the customer’s choice.
  • Delay Compensation Rule: under 3 hours → ₹500 meal voucher · more than 3 hours → meal voucher + lounge access · more than 5 hours → meal voucher + hotel accommodation covering only the delayed hours (not a full night’s stay).
  • Refund Processing Rule: refunds for airline-caused cancellations are processed in full within 7 business days, to the original payment method only.
  • Fare Difference Rule: a voluntary rebooking onto a higher-fare flight (not airline-caused) means the customer pays the fare difference. Agents cannot waive differences above ₹1,500 without supervisor approval.
  • Loyalty Tier Rule: Gold and Platinum get priority rebooking (first access to next-available seats) but no additional compensation beyond standard policy.

§4Allowed vs. prohibited actions

Allowed:

  • Rebook on the next available flight within 24 hours at no charge (airline-caused disruption)
  • Issue meal vouchers and lounge access per the delay compensation rule
  • Arrange hotel accommodation for the delayed-hours portion, where the delay qualifies
  • Initiate a refund request for airline-caused cancellations
  • Provide the customer’s own booking and flight status information

Prohibited (must escalate to a human agent):

  • Approving any compensation beyond the stated policy amounts
  • Waiving a fare difference above ₹1,500
  • Making exceptions for non-airline-caused disruptions (e.g., customer missed the flight)
  • Handling threats of legal action or formal complaints — escalated immediately
  • Processing refunds to a different payment method than the original

§5Tone reference

The agent’s voice follows the sample conversations in the pack: acknowledge the frustration, state the facts from the booking data, offer the policy options, and — when something needs a human — escalate warmly and immediately (“I want to make sure this gets the right attention…”). How this agent works

A conversational resolution agent grounded only in the data pack. It runs in one of two modes — the badge in the chat header shows which is active.

Two modes

  • AI agent — an LLM handles the conversation with the data pack as its only knowledge, and takes actions exclusively through six policy-enforced tools (rebook, refund, delay compensation, fare quote, paid rebooking, escalate). The policy layer is deterministic code the model cannot bypass — a disallowed request returns a policy error the agent must relay and escalate. Works with Claude (ANTHROPIC_API_KEY) or free providers: Groq, Google Gemini, OpenRouter — or, with no key at all, a keyless free endpoint the server probes at startup.
  • Rules engine — a fully deterministic fallback (keyword intent matching + the same policy checks) that runs with no API key, no internet and no dependencies, so the demo always works.

Architecture

  • Data layer — the pack’s profiles (§1) and booking table (§2), encoded verbatim. The agent can only see the verified customer’s own booking; other passengers’ data is never in its context.
  • Policy layer — the five service rules (§3) plus the allowed/prohibited boundary (§4) as explicit checks around every action. Each check emits a trace entry: Allowed, Blocked, Supervisor or Escalated.
  • Conversation layer — the LLM (AI mode) or intent matching (rules mode), with the empathetic tone of the §5 samples. Legal threats additionally trigger a server-side guard that forces immediate escalation.
  • Escalation model — out-of-policy requests are declined with the reason and an in-policy alternative, and escalated to a human on insistence (immediately for legal threats). The agent never approves beyond policy and never promises an escalation’s outcome.
  • Identity flow — the “New customer” entry starts unverified: the agent asks for a booking reference and calls verify_identity; no account data exists for it until that succeeds, and it never re-asks for what verification returns.
  • Knowledge base — the pack’s service rules live in a retrievable KB; the agent’s search_policy tool returns the verbatim rule text with section ids, which the console logs as KB retrievals.
  • Cases & human-in-the-loop — every conversation gets a Case ID and an audit ledger; escalation tickets land in the Resolution Console, where a supervisor can approve or deny them. The decision flows back into the live chat — an approved ₹2,000 fare waiver executes the free rebooking through the same policy layer and the customer sees the update within seconds.
